Privacy

OCTForge is built to run on your own machine. This page describes exactly what the application does with data, based on how it is built.

Last updated: 6 October 2026

In short OCTForge needs no account and no personal information. It contains no analytics, trackers or third-party scripts. Scenes, projects and exports stay on the machine running OCTForge.

No account, no sign-in

You do not need to create an account, sign in or provide any personal information to use OCTForge.

Where your work is stored

All scene configurations, projects and generated images are processed by the OCTForge backend running locally on your machine (127.0.0.1). Saved projects are written as JSON files to the projects/ folder on that machine. Exported files are generated locally and downloaded by your browser to wherever your browser saves downloads.

Scene configurations, projects and generated images remain on your machine and are not uploaded to OCTForge developers or Google. The browser separately contacts Google Fonts to retrieve the Outfit typeface.

What the application sends, and to where

The interface sends application-data requests to its own backend, under the /api path on the same local server. These requests carry scene settings, visualization and annotation settings, and project data needed for rendering, saving and exporting. Separately, your browser requests the Outfit stylesheet from Google Fonts and font files from Google's font delivery servers. Google may receive ordinary connection metadata when serving these files, but your scene settings, generated images and project files are not included in those font requests.

Outfit is loaded online from Google Fonts. If Google Fonts cannot be reached or you are offline, the browser falls back to the system UI font. OCTForge's icons remain self-hosted in the application's own assets/ folder.

No analytics, tracking or third-party scripts

OCTForge does not include analytics, advertising identifiers, tracking pixels, session replay or third-party scripts. It does not set advertising or tracking cookies.

No patient data

OCTForge does not collect, process or require patient data. Every image is generated from parameters you set. The application has no feature for importing, uploading or displaying a real scan, so there is no patient imagery to protect and none is sent anywhere.

Browser storage

OCTForge does not use localStorage, sessionStorage, IndexedDB or cookies. The current scene, undo history and view state live in your browser's memory for the length of the session and are cleared when you close or reload the page. Saved work persists only through the project files described above.

Changes to this policy

If future versions change what the application stores or sends, this page will be updated and the date at the top revised. Any change that adds an external request will be listed here explicitly before it ships.
